# Attempts, review and limits

- The first native/API browser regression fails on the old runtime because the
  new native horizon property is absent. No repeat of the failed old public
  `color` property experiment was made. The genuine baseline screenshot is kept.
- Unrestricted adapter red proof: 2 pass / 1 fail against the accepted adapter.
  A second release-order regression reproduces leaving colors on zero when a
  native panorama selection precedes its watcher: 3 pass / 1 fail. Both are fixed;
  the final complete runtime/Earth suite passes 134 tests. Initial restricted
  runner logs only summarize a test-file process; they are not per-test proof.
- The first controlled native compilation/UI build completed, but its wrapper
  reached the attestation step before the new attestor file existed. That failed
  attempt remains in `output/n1/native-horizon/native-build-initial.txt`. The final
  complete recipe succeeds in a fresh directory, and all native/frontend bytes
  reproduce exactly. Only the successful complete run is build qualification.
- Initial visual test assumed native presentation always restores a panorama.
  Native zero can itself be the prior choice. The test was corrected to verify
  preservation/restoration of native choices/colors, and standalone Guéreins is
  independently verified. No production workaround for that test assumption.
- Earlier navigation runs were intentionally interrupted before the demonstrated
  release-order fix and the stale native-identity metadata correction. Their logs
  remain under `output/n1/native-horizon/`; final 44-group proof is separate.
- Docker returned equivalent mount arrays in different order. A byte-order
  assertion failed; comparing complete entries sorted by destination proves all
  mount settings unchanged and read-only. No mount was altered.
- The initial 2.5-second dark capture has zero bright pixels in the sampled sky
  region. Comparing it with a separately loaded baseline failed bright-pixel
  equality. That capture and failed attempt remain retained; no cause is asserted.
  The report's after image is the later Night OFF capture with visible stars.
  Exact cross-load brightness equality is not an acceptance claim. Controlled
  same-runtime native-color-only changes match all sampled 184 desktop / 42 mobile
  above-horizon bright pixels; no pixels above the horizon are recolored by the
  circle. Cold-start rendering time is not newly qualified by this task.
- Native HiPS iterator warnings, missing dense-star tile HTTP 404s, navigation
  request aborts and existing external/provider availability failures remain in
  raw traces. They are distinct from JavaScript page exceptions (zero). Exact
  summaries are in `browser-limits.json`. No unrelated tile/provider repair.
- Chromium software rendering and emulated mobile/touch do not qualify physical
  device performance. The owner's scrolling acceptance remains the owner's
  decision, not an inference from these automated tests.
- Full backend/provider and separate astronomy deep-link suites were not rerun:
  API, catalog identity, astronomy data, selection and scientific math are unchanged.
  Native scientific/source preservation is checked against pinned inputs; this is
  not a new catalog-wide science-validation claim.
- Review was performed by the single implementing agent, as required by AGENTS.
  It checked patch scope, inline ownership/default initialization, shape-only
  callbacks, release-order restoration, native promotion guard, pinned build/source
  closure, exact served JS/WASM, rollback coherence, and unchanged camera/protocol.
  The previous P2 is already resolved; current PR threads are checked at delivery.
- Committed text logs normalize trailing whitespace only. Original command output,
  failed attempts and full captures remain locally served under
  `http://127.0.0.1:4202/evidence/native-horizon/`.
- The unified native patch has a required space-only context marker for an
  unchanged empty C line. A file-specific `.gitattributes` rule permits that valid
  diff syntax; C source and other files retain their normal whitespace checks.
